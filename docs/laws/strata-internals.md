# Strata (hydragen-unified) internals — flag map and measured constants

Flag map (verified from `./bin/strata --help`, 0.35.0-hydragen-unified):
- `--expert-cache N|auto` — VRAM expert slots; hit rows run on the grouped kernel `moe_hit_grouped_s2`.
- `--expert-cache-device1/2/3 N|auto`, `--expert-cache-remote-placement stripe|layer`, `--remote-expert-opt`, `--peer-device N`, `--peer-slots`, `--peer-prefill-rows` — multi-GPU expert pool split already exists in-engine; pool-split fleets are an enablement problem, not a build.
- `--resident-cpu-experts` / `--resident-experts` — pinned-RAM cold experts with adaptive swap (the RAM tier). CPU pool: `--pool-workers`, `--pool-tasks`.
- `--expert-profile FILE` (warm start), `--expert-profile-save FILE`, `--expert-profile-save-every S` — live profile persistence.
- `--dump-routing PATH` — per-position, per-layer routed expert ids and weights; the routing-trace tool.
- `--expert-cache-per-layer` — per-layer slot policy (default arrival order underperforms).
- `--batch N`, `--batch-mtp`, `--prefill auto:N`, `STRATA_PREFILL_CPU_SHARE=auto`, `--shared-late`, `--pcie-frac`, `--kv k8v4`, `--kv-resident N`, `--conversation-cache-mib`, `--prompt-cache-tail`, `--mtp`, `--spec N`, `--coupled-draft`, `--adapt-every/-swaps/-decay/-async`.
- `STRATA_KV_GROW=1` + large `--kv-resident` caused a reproducible first-request abort on the 12 GB node — do not combine.

Measured constants (iq3_XXS on 3080 Ti 12 GB unless noted):
- Expert blob IQ3_XXS ~1.68 MiB; full set 48x512 = 24576 slots; auto budget measured 2343 slots ~ 3940 MiB ~ 49 experts/layer.
- One added batch slot ~660 MiB (~390 blobs, ~17% of expert cache).
- Warm learned profile: hit 77-87% (vs 63-68% cold), decode 106-111 tok/s.
- 3090 (iq3_s, 24 GB, 4068 slots, batch 8): hit 99.8%, avg 7.17 rows/window, aggregate flat ~91-93 tok/s from N=2 to N=8 — rows per weight load ~1.2; the wall is kernel granularity/row sharing, not VRAM.
- Effective host-path (PCIe+DRAM) streaming bandwidth fitted ~16.5 GB/s.
- Model (Qwen3.8-Flash-Next): 125B total / ~6B active, 48 layers (36 Gated DeltaNet + 12 QSA sparse-attention), 512 experts/layer, top-10 + 1 shared, hidden 2560, expert intermediate 640, ~51B n-gram/engram table (host RAM/NVMe mmap).
- KV is cheap on this hybrid model: GDN state ~38 MB/stream fixed; QSA ~12 KB/token int8. A 16k stream ~200 MB total. KV is NOT the concurrency bottleneck; expert sharing is.
- CPU-expert floor on Ryzen 5900X (AVX2 only): ~316 MFLOP/token expert work, ~0.3-0.6 TFLOP/s sustained AVX2 INT4 -> all-CPU-expert decode ~1-3 tok/s. CPU is a last-resort tier, not a throughput tier on Zen3.

Serving wrappers:

- Windows 3090: nssm service reads the same JSON; ImagePath `C:\Hydragen\tools\nssm.exe`, Application `.venv\Scripts\python.exe -m hydragen.cli --engine strata --config hydragen.json`.

Kernel-structure spike (2026-11-05, verified: scratch/moe_dequant_final.py, results_dequant.txt): grouped Triton fused INT4-dequant kernel (join-interleave single-dot variant) sustains 350-500 GB/s stored-INT4 on the 3090 (415-498 at E=48 N=640), per-expert cost grows only x1.16-1.41 from M=1 to M=16 — row amortization nearly free. Two-pass dequant-then-GEMM is 5-10x SLOWER (41-72 GB/s): dequant must be fused in-kernel. Ungrouped mv launch-bound ~20-34 us/expert. Triton on Windows = `triton-windows` package (no official cp312 wheel). fp16 bitcast dequant: chain `-1024.0 -7.5`, never `-1031.5` (unrepresentable). Numbers taken alongside the busy service — conservative.

WAVE TEST (2026-11-05, /tmp/bench_waves.py + /tmp/knob_wave.sh) — decisive NEGATIVE, kills the domain-affinity-admission patch idea. Concurrent same-domain waves vs concurrent mixed-domain waves at the same batch size are within noise: batch4 warm same-domain math 42.8 / sysadmin 41.1 / prose 40.0 vs mixed 40.8; batch2 warm same-domain 49.9/48.3 vs mixed 47.1. batch2 > batch4 in every case (batch4 hits fall to ~50-54% from ~70%, PCIe +4-6% vs +1-2%). ROOT-CAUSE CORRECTION of the Step-1 'domain affinity' number: the domain-pinned low union was TEMPORAL locality within one contiguous same-domain STREAM (adjacent rows share 4.7/10), NOT cross-request domain affinity. INDEPENDENT same-domain prompts (different tasks, not adjacent) share only ~1.9-2.4/10 — barely above the 0.39 random floor. MTP/coupled-draft ALREADY exploits the real temporal adjacency (draft+verify rows of one stream) at batch2 -> that is the 70% hit. Adding batch slots adds non-adjacent cross-stream rows whose demand does not amortize, so hits drop and throughput falls. CONCLUSION: there is no exploitable cross-request expert reuse for the Qwen3.8-Flash-Next router; a scheduler that co-schedules same-domain requests buys ~0 (marginal ~10-15% at N=2 only, vanishes at N=4, dominated by batch-slot cache cost). Do NOT implement ExpertLocalityPolicy-style admission. Aggregate concurrency on a 12GB node is hard-capped by (expert-cache hit rate × grouped-kernel structure), not by scheduling policy.
