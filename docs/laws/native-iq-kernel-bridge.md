# Native IQ kernel bridge (M9): GGUF IQ donor -> Strata grouped MMVQ under SGLang

Goal: replace the Triton w8a16 staged path with Strata's native grouped MMVQ kernel reading IQ blobs GPU-side — 3x wire diet, 20x GEMM, no device dequant.

## Donor GGUFs
- IQ-labeled Strata GGUFs under `~/.models_backup/Strata-data/models/` on the reference host (split shards, ~74 GB, arch `qwen4exp`). Fused 3D expert tensors `(K,N,E)` — last dim = expert; byte order == per-expert flatten of the torch store, extractable with plain preads at `(eid*K*N + i)*2` element offsets. No python gguf package installed — parse the header/tensor-info table manually in chunks.
- Expert quant types VARY per layer (seen: 10,17,18,20,21,22,42). Upstream ggml has no type 42, but a llama.cpp FORK may map 42 to a known type (this node's fork: 42=q2_0, CPU-decodable) — ground-truth enum numbers/names against the fork's own headers and libggml before concluding a type is undecodable; only Strata `dequant_f16` (CUDA) can be assumed available as fallback. `iq_row_bytes(ty, cols)` returns per-ROW bytes — total = rowbytes x rows; it answers per-type queries, `iq_supported(ty)` gates.
- IQ3_XXS-labeled donors mix IQ2_XS gate/up + IQ4_NL down per expert blob: 473,600 + 473,600 + 921,600 = 1,868,800 B/expert vs 5.6 MB fp8. Same weights as q4e-fp8 (mean GEMM cos 0.961 vs FP8 ref = requant recipe, not finetune).

## Kernel ABI (libstrata_iq_kernels.so — no python bindings; ctypes-wrap exports)
- `strata_vllm_native_expert_grouped(ne, grp_ptr u64[ne], eid i64[ne], grp_start i64[ne+1], ent_dst i64[E], ent_tok i64[NT], x_q8_1, out_f32, stream)` — applies gate/up/down + activation INSIDE the kernel: `h = act(x@g) * (x@u); out = h@down`. `out` is `[entries, n_embd]` (reference bench must model the full forward, not gate-only).
- `x_q8_1`: 20 bytes per 16 elements (fp32 scale + 16 int8). Undersizing (e.g. 9 B/16) yields silent NaNs.
- `grp_ptr[i] = blob_base + eid[i]*blob_bytes`. Blob layout = `expert_blob_info(ty, cols=n_embd, rows=n_gateup)`: `gu_row*GU*2 + d_row*H` bytes (IQ2_XS gu row 740 x 640 x2 + IQ4_NL d row 360 x 2560 = 1,868,800).
- `dequant_f16(ty, ptr, rows, cols, ld, row_idx, out)` takes DEVICE ptr + row indices — CUDA side. `iq_dequant_f32` is a CUDA launcher: ctypes-calling it with host pointers = illegal memory access, never do it.
- CPU dequant for audits: `dequantize_row_*` is NOT exported from prebuilt `libggml-cpu.so` — compile a shim (ggml-quants.c + a C wrapper, `~/hydragen-experimental/dq_shim.c/.so`) linking libggml + libggml-cpu. Inside a double-quoted ssh `cc -Wl,-rpath,$HOME/...` line, `$HOME` expands LOCALLY (wrong machine's home) — write absolute rpaths.
- GGML type table drifts across llama.cpp versions — decode enum values by `gguf_type_size`, not numeric assumptions.

## Extraction pipeline (scripts on node: m9c_extract_iq.py, m9c_blobs.py)
1. pread per-tensor IQ blocks byte-faithful from donor -> `hg-store-iq` (per tensor, ~46 GB).
2. repack per layer to `hg-store-iq-blobs/L{NN}_blobs.bin`: 512 contiguous `[gate|up|down]` blobs, `manifest.json` with per-layer types (40 GB). Native shim + benches read ONLY this.
3. Verify by sampling: byte-identical vs GGUF offsets + dequant sanity. FIDELITY METRIC = cos, not stddev: codebook-offset types (e.g. IQ2_XXS, mean-shifted) fail naive std checks while byte-identical.

## Serving shim (pyhook/hydragen_moe_native.py, HG_MOE_NATIVE=1; sitecustomize checks native before HG_TRITON_MOE)
- Pinned host tier of IQ blobs (HTIER experts/layer; 288 = ~26 GB — the fp8 96-expert pinned ceiling x3 at the same driver budget because blobs are 3x smaller) + device blob cache N=24.
- KEY difference vs Triton path: device cache stores blobs COMPRESSED (1.87 MB) — N costs 45 MB VRAM total, so the N<=6 staging-budget rule from the Triton path does NOT apply; quantize hidden states to q8_1 once per chunk, ONE grouped call per layer covers all routed pairs, torch combine (`strata_vllm_moe_combine_multi`) from Triton is reusable.
- Measured (L0 blobs, 8 experts, NT=32, warm): 0.65 us/expert vs Triton w8a16 13.2 us; fidelity cos 0.9999 vs fp16-dequant SwiGLU reference. Microbench: `~/hydragen-experimental/m9b_native_bench2.py`.
- Launch: `launch_phase2_m9.sh` (M8 shape + HG_MOE_NATIVE=1, launch-tuned CACHE_N=12, HG_NATIVE_TCHUNK=32, HTIER=288). RESULT: native serving boots and is faster (see references/phase2-native-iq.md) but the IQ3_XXS expert-only splice FAILS the quality battery — plumbing works, quality does not.

## Whole-model donor splice (M10: rebuild every non-expert tensor from donor GGUF context)
Motivation: GSQ-RCO quality is a calibrated whole-model system — IQ experts spliced into FP8 attention/shared context removes the compensation and fails the battery. The splice rebuilds the checkpoint (q4e-fp8 -> q4e-iq): non-expert tensors whose donor GGUF counterpart is QUANTIZED are rebuilt via CPU dequant -> requant to block-FP8; tensors whose donor counterpart is float-class are kept as HF bytes (they are tier-invariant); expert and ngram safetensors shards are hardlinked (native IQ blob store / loader-skip serves them). Disk math: new bytes ~= non-expert shard total (~44 GB); guard the misc-file copy loop with `os.path.isfile` (a `.cache` dir in the source trips shutil as IsADirectoryError).
- dense.bin is NOT a usable donor-context import for a different engine: Strata pack dense.bin holds only float-class tensors (routers, hc mixers, ssm gates, ple projections, norms) and conversions.json shows zero conversions for that tier; quantized dense tensors (attn IQ4_XS/Q6_K, shared-expert IQ, token_embd IQ3_S, lm_head Q6_K) and the ngram table exist ONLY in the GGUF.
- SPLIT-GGUF OFFSET LAW: each shard carries its OWN tensor-info table and offsets are LOCAL to that shard's data section (big tensors like a 28.8 GB PLE table get their own 1-entry table in their shard; shard 1's 1223-entry table tiles only shard 1). A merged table with global cumulative offsets silently reads expert bytes as dense tensors = garbage/nan dequants that look like dequant-type bugs. Store (shard_idx, offset) per tensor; data is at that shard's (header_end + 31)//32*32 + offset. Validate: for each shard, min off == 0 and max off+size == shard data size.
- Hand-rolled GGUF v3 parser grammar: magic + u32 version + u64 n_tensors + u64 n_kv; kv value types are u32; string KV values = u64 length then skip ONLY the payload (double-counting the 8-byte length field derails every subsequent entry); tensor name = u64-len string, dims u64[], type u32, offset u64. Keep every Python file handle that backs an mmap alive (mmap via a transient `open(...).fileno()` goes garbage once the handle is GC'd).
- QUANT ENUM + BLOCK-SIZE GROUND TRUTH per fork: a llama.cpp fork can renumber ggml types (this node: 14=q6_K, 21=iq3_s, 23=iq4_xs, 42=q2_0) — never hardcode numeric types or block sizes from upstream ggml.h; query the fork's libggml at runtime via ctypes (`ggml_type_size`, `ggml_blck_size`) and read enum names from the fork's headers/strings. iq4_nl rows are 18B per 32 elems (ggml_row_size is correct; a '144-byte stride' idea is wrong).
- LAYOUT LAW — verify empirically BEFORE implementing any HF<->GGUF row transform: llama.cpp conversion may define a reorder class (e.g. `_LinearAttentionVReorderBase` with num_k=16/num_v=48/head=128) that DID NOT FIRE for this checkpoint's conversion; source-derived transforms produced worse cos than raw. Recipe: dequant candidate rows (float32), L2-normalize both matrices, argmax of `cand @ needle` per probe row — one probe tells identity vs permutation outright (tiled `v*nk+k` -> grouped `k*r+v` decodes in ~8 probe rows). This donor's GDN attn_qkv/attn_gate/ssm_out rows are ALREADY in HF order (0.99 cos identity).
- Checkpoint->GGUF name map is 1:1 by suffix (attn_q/attn_k/attn_v/attn_output, attn_qkv/attn_gate/ssm_out, ffn_*_shexp, ffn_gate_inp, token_embd/output, ple_*, hc_*, per_layer_token_embd); indexer.index_qk_proj = concat of donor indexer q+k rows. Match tensor suffixes with `endswith`, not split('.') indexing ('.weight' suffix poisons the base name).
- Builder: `~/hydragen-experimental/m10_build_v2.py` (modes --sanity/--only/--ngram; sanity = per-tensor cos vs the HF fp8 tensor; expect 0.987-0.9998 cos on quantized donor tensors, 1.000000 maxdiff 0 on float-class).

## Cost gotchas
- Backgrounding a long build over ssh: `nohup cmd > log 2>&1 &` inside `ssh '...'` keeps the channel open until the child exits (and an outer cleanup like `rm -rf` in the same one-liner can stall the whole turn on an approval timeout). Detach fully — `setsid ~/sg-env/bin/python -u builder.py > build.log 2>&1 < /dev/null &` — keep destructive cleanup as its own pre-approved call, then poll the log in separate ssh calls.
- GGUF metadata probing: dims tables are tiny but tensor arrays are huge; return `(count, str(type(elem)))` for arrays >8 elems or the scan hangs dumping millions of ints.
- Expert-type audit across all 48 layers BEFORE designing dequant — type mix decides feasibility; for custom-class types (42), check whether the installed llama.cpp fork actually maps them to a decodable ggml type before ruling out a ggml-routed dequant path.
