# M25 long-context (22.5k sessions at 131k ctx) + prefill-isolation laws — §97/§98

Context-vs-residency curve law (0.1.59, IQ3_XXS, batch 2): 128k ctx does NOT scale KV cost linearly — above ~32k the engine auto-switches to KV streaming (20480 cells/layer VRAM window + pinned-RAM remainder), costing only ~23% of expert slots. expert-cache auto slots are internally capped (~2400 on 12 GB regardless of extra free VRAM), so "shrink ctx -> more slots" is false; the short-ctx speed win is attention/decode-path cost, not slots. Sweep --max-context as a probe only; judge arms on slots + ladder + telemetry lines together.

1. Long-context decode is NOT the tax: cached 22.5k-ctx streams decode 122-152 tok/s spec'd (95-98% draft accept) and 40-68 in batch windows, at/above short-ctx levels. KV streaming holds 20480 cells/layer in VRAM + pinned-RAM remainder; 74-97% block-read hit rate.
2. Strata reuses prefixes at 22k scale: "22528 reused + 7 read", checkpoint restore ~60-250 ms, reused_kv_bytes>0 (KV bytes travel with the conversation). RadixAttention's compute half exists; only shared-block storage dedup is SGLang-only.
3. Parking cost: ~394-437 MB per parked 22.5k-token conversation (int8 KV + snapshot). --conversation-cache-mib is a byte-capped LRU with graceful evictions; size it: 14 sessions@22k vs 2@128k in 6 GiB.
4. THE tax is admission, and the mechanism is the prompt path's expert-cache LOAN, not naive chunking: the prompt path borrows the top expert-cache slots for its ring buffers and refills them after the read (boot log: "prefill ring borrows N slots" — 2168 of 2410 = the 90% default). During a cold read, decode's resident experts are evicted twice (once for the ring, once on refill) -> windows stretch 2x (53-56 ms), routed VRAM hits collapse to 21%, co-resident streams drag to 12-43 tok/s. Isolation knobs exist as STRATA_* envs (grep generate.cpp for STRATA_PREFILL): STRATA_PREFILL_LEND_PCT (cap on loan %, defaults 90/85/100 by card headroom), STRATA_PREFILL_RING (ring slot count, the explicit A/B arm), STRATA_PREFILL_BORROW / --no-prefill-borrow (reserve prompt VRAM whole-session instead of borrowing), STRATA_BATCH_YIELD_CHUNKS (default 8 — prefill reading is already chunk-yielded by default), STRATA_ADMIT_MERGE_FIRST, plus serve-layer admission knobs in serve/server.py: STRATA_ADMIT_SHORT_FIRST, STRATA_COALESCE_PREFILL/STRATA_COALESCE_TOKENS. serve/server.py spawns the engine with plain subprocess.Popen, so envs exported before launching serve are inherited by the engine — env-knob A/B arms need no config edit, only kill+relaunch in a script FILE (pkill-self-match law).
5. Prefill scales with prompt length: ~700 tok/s at 1.3k, 2400-2800 tok/s at 22.5k (ring amortizes). 128k cold prefill ~= 45-55 s.
6. Ladder confound law: re-running the same prompts across concurrency levels mixes cache-hit streams; separate cold vs warm via engine telemetry lines (reused counts, window rows, hit rates), not request layout.

## §99 prefill-isolation config sweep CLOSED
7. Config knobs cannot isolate decode from cold-prefill poison: --prefill 8192 free-but-neutral, 4096 bad trade, COALESCE_PREFILL no-op, PREFILL_LEND_PCT=50 catastrophic (ring = MMQ staging rate-limiter; shrinking it collapses prefill 2.5-5x and stretches poison over the whole read).
8. Engine default lend = 90% of expert-cache slots (floor keep 128). Poison duration ~= prompt_tokens / prefill_rate. Fix must be engine policy: pin top-N hot decode slots WITHOUT shrinking the ring; refill ordering; or probe server.py --split-serve PREFILL,DECODE.
9. Swap law: serve holds :8181 ~5-15 s after TERM; kill loop must wait for curl-refused before relaunch.
10. kVerify=8 is static constexpr at q36_engine.cu:1165; widen = one constant + buffers.

## §100 wide-batch closed + one-budget law
11. --batch 4 on 12 GB IQ3_XXS: expert cache 2456->1663 (-32%) at boot; co-resident streams 9-19 tok/s; C1 172->142.5. Wide continuous batching loses to 2-users+drafts on one 12 GB card. Native IQ packs cannot boot with --spec 0 (T>=2 required).
12. server.py --split-serve PREFILL,DECODE is two-card only (two engine loads, prefill_gpu/decode_gpu); infeasible on single-GPU the reference host.
13. Long answers amortize MTP: 432-token answers sustain 172-185 tok/s spec'd (accept ~98%); short answers 90-130.
14. Engine already lends coldest TAIL slots first + refills after; poison is residency arithmetic (22.5k-token footprint vs ~12% surviving residency), not fixable by policy patch. Checkpoint reuse makes it first-turn-only.

## §101 --no-prefill-borrow arms (poison immunity real, paid in permanent residency)
15. --no-prefill-borrow carves prompt chunk buffers + ring PERMANENTLY. At --prefill 4096 the carve costs 1720 expert slots (2456->736): co-resident decode during cold 22.5k reads holds 23-26 tok/s instead of cratering to 12 (zero cache interference), but C1 spec decode collapses 172->83.5 (7% residency). Not adoptable on 12 GB — permanent tax > transient poison — but it PROVES the poison mechanism is cache interference.
16. NEVER combine --no-prefill-borrow with big chunks (auto:16384) on 12 GB: engine boots and serves HEALTH_200 but verify windows cannot instantiate ("batch instantiate: out of memory", every request HTTP 400). A HEALTH_200 engine can be inert — send one real completion before believing a boot.
17. anti-CoW contrast: npb removes interference by SEPARATING budgets (pays experts); CoW KV pages remove interference by DELETING duplication (can create budget: shared-prefix sessions pay ~0.05 GiB instead of ~0.36 GiB per slot). Cross-session page sharing requires bit-identical prefix KV — chunk-size-dependent GEMM numerics break that; canonical chunk plan or tolerance-keyed dedup is the subtle part.

## Profile re-rank loop (self-learned hot set)
18. `--expert-profile-save P --expert-profile-save-every MIN` in serve mode persists what the adaptive tier learned (VRAM residents first, then routing counted since start) on QUIT and between requests; next boot `--expert-profile P` starts warm. Loop: boot with save flag -> drive representative traffic (multi-turn growing sessions + short Q&A + domain prompts) -> SIGTERM serve / QUIT engine -> relaunch from the saved profile -> A/B hit-rate lines + decode ladder + QC battery.
19. tools/make_profile.py pitfall: the shipped base profile ranks ALL 24576 pairs and `take()` skips already-ranked pairs, so a plain `--base` run CANNOT be moved by any trace (output = base again). Use `--reorder` (traces first) or `--no-base` when a workload trace must decide the top.

## §102 expert-profile re-rank CLOSED-NEUTRAL
20. On the q36 C++ engine the expert-profile sets ONLY the boot pre-load: the adaptive tier (adapt-every 1, adapt-swaps 400, decay 0.97) converges to the traffic's hot set within the first windows, so a traffic-learned top-K ties the shipped profile in steady state AND at first request — even when the profile was learned from the exact bench traffic (learned 175.1 vs shipped 174.1 spec C1, walls identical). Do not build offline profile re-rank arms on this engine; `--expert-profile-save` is worth keeping ONLY as a restart-warmup affordance. Expert hot-set residency is NOT the scarce axis anymore — remaining walls are budget (slots vs experts, §100) and rows (kVerify, §95).

## KV window memory layout (read before any KV-hash / CoW / page-sharing patch)
21. Per-session VRAM KV arrays `Sess::kc/vc` are FP32 `float*`, allocated `n_head_kv * ctx * head_dim` per attention layer (alloc_session in q36_engine.cu), layout [head][cell][head_dim] — cells are strided, not contiguous across heads. `ctx` here = the session WINDOW (--kv-resident cells, e.g. 20480), NOT --max-context: cells above the window live only in the pinned/stream tier (int8) — clamp any D2H copy of prompt cells to min(prompt_len, ctx) or cudaMemcpy reads past the allocation (illegal access abort). GDN layers keep constant-size conv/S state (kc/vc nullptr); the MTP block appends its own kc/vc pair at index n_layers.
22. Tier taxonomy: live sessions = fp32 KV window in VRAM (~0.36 GiB per 20480 cells + slot state); parked conversations = host-RAM checkpoints only (~400 MB per 22.5k, int8, ZERO VRAM — resume re-admits a slot); so parking capacity is a host-RAM/TTFT concern, never a VRAM lever.
23. Prefix-determinism spike (M-C0 pattern): the discriminator for cross-session KV bit-identity is the BOOT-TIME chunk plan (--prefill value differs per boot), not concurrent contention — the engine serializes prompt admissions, so run same-prompt arms as the FIRST request after fresh reboots with different --prefill. Env-gated hash hook: D2H-copy each kc/vc head-slice [0, min(pn,ctx)), FNV-64 the bytes, log per request. Anchor the single-path hook at `E.sess[(size_t) E.cur].pos = E.pos;` (scope: ids, reuse, fresh, ss). Scope law: the serve runner is a WRAPPER around Engine, not a member — reach internals as E.st / E.m->g.* / E.ctx / E.sess, and qualify the nested struct `Engine::Sess&`; wrong scope reads `identifier st/m/ctx undefined` at the injected lines.
